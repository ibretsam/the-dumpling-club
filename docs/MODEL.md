# The dumpling models

`assets/dumplings/<type>.glb` are binary glTF 2.0 files, one per dish, generated by
`node tools/build-dumpling-glb.mjs` (`npm run build:model`) from `js/dumpling-geometry.js`. Each
contains two meshes, named `<Type>Body` and `<Type>Bitten` (for example `JiaoziBody`,
`JiaoziBitten`). Attributes are quantized with `KHR_mesh_quantization` (int16 positions and
normals, uint16 UVs, uint8 colours; ~1.5e-5 units of position error), which the vendored loader
decodes natively; code that reads vertices goes through `BufferAttribute.getX/Y/Z`, which
denormalizes. Files are 0.7–0.9 MB each instead of 7 MB for the old single float file, and the
site only waits for the dish it needs first.

| Type id | Family | Notes |
| --- | --- | --- |
| xiaolongbao | lathe | meridian profile revolved around +y, 18 pleats swirling into a knot |
| jiaozi | crescent | cross-section swept along a bent centreline, 7 pleats scalloping the crest |
| potsticker | crescent | as jiaozi, 6 pleats, browned base painted at runtime |
| hargow | crescent | rounder bonnet, 11 fine pleats, translucent skin with an inner filling mesh |
| siumai | opentop | gathered wrapper with a ruffled collar and an exposed filling dome (vertex colours) |
| bao | lathe | large fluffy bun, 12 soft pleats |

Conventions: origin at the base centre, base on y = 0, +y up, face toward +z, 1 unit = 10 cm.
UV u runs across the front (0.5 at the face centre), v from the base upward; each type's
`faceUV` rect (in `DUMPLING_TYPES`) is where `js/faces.js` paints the face. Bitten meshes carry
`COLOR_0` (the crater is coloured with the filling). The site requests every dish file at boot,
waits only for the welcome dish, mounts the menu samples as the others arrive, and falls back to
the procedural generator for any dish whose file cannot be loaded.
